## Custom hardware and facilities

A chip specification captures architecture, supported workload, and memory design. Specification work and prototype validation have separate staff/work meters and availability boundaries. Prototype validation records the model and held-out report used, then reveals a fixed production yield. Renaming or repeating an order cannot reroll that yield.

Qualified production orders purchase one, two, or four rack slots. Fees use attempted capacity; yield determines useful compute. Manufacturing has an explicit lead time. Delivery creates inventory, followed by installation through the existing infrastructure controls. Custom racks continue to need operations staff, power, cooling, connected memory, fixed upkeep, and physical-work charges. Their workload and architecture restrictions affect actual grants.

Fast fabric is installed at colocation or an owned site. Elapsed time, infrastructure effort, and development validation must all finish before it becomes operational. The network has ongoing fixed and staff costs. Separate sites, hardware classes, and cloud memory remain distinct.

The production panel’s payback estimate uses the shared engine helper. It exposes utilization, yield, useful capacity, effective work, entry and production costs, equivalent cloud costs, recurring expenses, estimated savings, and exclusions. It is a planning estimate, not a demand forecast or guaranteed return.

## Save compatibility and recovery

Valid schemas 1–4 migrate to schema 5 without advancing time. The browser primary key and single-writer lock are unchanged. Before the first upgraded write, the exact prior bytes are archived under the appropriate recovery key:

| Original run | Recovery key |
| --- | --- |
| Wave 0 / schema 1 | `frontier-lab.wave0.original` |
| Wave 1 / schema 2 | `frontier-lab.wave1.original` |
| Wave 2 / schema 3 | `frontier-lab.wave2.original` |
| Wave 3 / schema 4 | `frontier-lab.wave3.original` |

Earlier originals are never overwritten. Archive failure prevents primary replacement. A failed primary write retains the old primary and any successful archive. Invalid or unsupported input blocks automatic overwrite and remains exportable. Explicit replacement retains the prior raw run.

The schema 4 fixture and three-week oracle came from the actual published Wave 3 engine, `aa7e3d6f8d1d2b3a4e567b7ead047dc2f87afddd`. Its authored QA start was followed by normal commands. The archived save includes live agent review and license delivery plus queued company work. It was not made by rewriting the version fields on a current snapshot.

Saves remain browser-local with portable JSON export. One tab owns the clock and writes. Hidden pages pause, and there is no offline catch-up or account synchronization.
